# 开发与接力

## 目录与扩展位置

| 目录 | 所有权 |
|---|---|
| product/chat | 工具桥、实体确认、guard、最小常驻 policy |
| product/skills/chat | 研究方法、委托生命周期、投资事实、通知偏好四个按需 Skill |
| product/tools | 66 项研究契约、62 个生效研究工具及有界 worker 工具 |
| product/bundle | chat/worker 装配及已知历史 patch 兼容基线 |
| product/ui | 现有四入口、Host 与桥接组件 |
| sidecar/huohuo | 权威业务状态、实体、证据、委托、投资事实、通知 |
| distribution、runtime | 安装、生命周期、后台 worker、Python 发现 |
| tests、scripts | 受控夹具、聚焦回归、构建/打包/导出 |

一项任务使用独立特性分支与 worktree，唯一写入者。服务端口、实例、缓存也必须隔离；不要借用他人的依赖或实例。提交、推送、合并、发布、服务器访问各自按明确授权执行。

## 修改 Skill 和工具

先读 [Skill 与 Tool 能力目录](Skill与Tool能力目录.md)。其中第 6 节列出注册事实源及同步清单；新增、修改、删除能力必须同步更新名称、数量、可用性和入口说明。页面新增业务操作须在第 5 节评估聊天 Tool 与 Skill，明确复用、组合、扩展或暂未接入原因；Skill 不替代执行器或授权。

专业方法写入标准 YAML frontmatter + SKILL.md。描述承担路由，要覆盖实际研究对象及触发条件；不要把持久状态或权限写成只有模型遵守的提示。增加 Skill 时同步 `product/chat/policy.ts` 的允许名单、原生目录回归和相关场景。普通财务研究的报告期/年份、basis、单位和口径说明属于 research-chat，不要求先创建委托。

聊天仅加载 bundled chat 目录；默认 home/cwd Skill 扫描关闭。guard 同时限制工具名和 Skill 名称；产品文件应视为受信代码，用户源码写权限不属于模型能力。不要开放 bash、文件工具或 subagent 作为“补救”。worker 保持仅 `read_security_snapshot`。

研究工具参数事实源为 Python `tool_contracts.py`，修改后 `npm run tools:generate`；可信主体来自会话和后端，不允许模型填 `authorized=true`。不同权限写操作保持独立，不合成万能工具。现阶段没有工具延迟曝光，62 个生效研究工具 schema 仍常驻；不要将 Skill 正文缩小宣传为整体输入、token 或成本同比减少。

## 聚焦检查与回放

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r sidecar/requirements.lock
export HUOHUO_PYTHON="$PWD/.venv/bin/python"
npm ci --ignore-scripts
npm run check
npm run build
HUOHUO_CHAT_TEST_PORT=18812 node --test --test-concurrency=1 lib/tests/chat.test.js lib/tests/research-tools.test.js lib/tests/entity-tools.test.js lib/tests/progressive-skills.test.js lib/tests/chat-upgrade.test.js
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=sidecar:tests "$HUOHUO_PYTHON" -m unittest test_entity_confirmation test_research_tools test_execution test_research_acceptance -v
npm run smoke:skills
```

`smoke:skills` 使用真实 DSH loop、原生 Skill loader、HTTP API 和 SQLite，模型/目录为确定性夹具，不访问真实 provider。默认 API18810/Web18811，通过 `HUOHUO_SMOKE_PORT`、`HUOHUO_SMOKE_WEB_PORT` 覆盖。每次创建自己的数据，目录、工具回执及副作用报告位于 `artifacts/skills-smoke`。夹具不进入发行 tgz。

```sh
npm run smoke:skills -- --serve
```

保持进程后，在其 `artifacts/skills-smoke/runtime.json` 的本地 URL 打开浏览器。输入“回放 U01：确认委托 600519 半年报收入研究，仅在产品内查看”，完成真实原生选项确认，再到委托查询核对合成基准、证据和刷新。非法工具用“回放 R09”。Ctrl+C 清理本次服务。

可选自动浏览器验收：本机已安装 Playwright 及 Chrome 时运行 `node scripts/uat-skills.mjs`，或用 `HUOHUO_PLAYWRIGHT` 指定可导入的 Playwright 模块。它不安装浏览器，截图保存在 artifacts；没有此环境可按上述步骤人工验收并记录限制。

```sh
HUOHUO_SMOKE_PORT=18813 npm run smoke
```

完整后台受控冒烟会从 tgz 建立新实例，覆盖鉴权、幂等、成功、截断失败、显式重试、来源失败、取消与重启。首次联网安装较慢；报告与中断恢复方法见启动指引。本轮不需要每次改文档都重跑它。

## 打包与导出

```sh
npm run pack:release
npm run handoff
```

发行 tgz 包含构建产物、运行源码、UI、Skill、锁和第三方声明；纯源码导出包含源码、tests、锁、资源及当前指引，不包含 node_modules、实例、数据库、缓存、构建产物、历史机器路径或 `.git`。脚本以白名单导出，输出在 `artifacts/handoff/`，保存清单与 SHA。归档中的产品根没有 `next/huohuo` 前缀。再次导出只允许覆盖与其来源清单完全一致的原目录；若出现 `.git`、修改/缺失源码、未知文件或缓存目录，一律拒绝。请保留同事工作并选择新的工作位置，不删除内容以绕过保护。独立构建验证应从 ZIP 解包到另一个临时根。

从导出根重新 `npm ci --ignore-scripts`、check/build 和 `smoke:skills` 是独立性验证。最终 tgz 还须仓外安装/启动，源码链接运行不能代替它。

`scripts/verify-release.mjs <tgz> <独立验证根>` 验证生产 consumer、两 Profile 与真实浏览器导航；须通过 `HUOHUO_PYTHON` 指定本轮独立准备且锁版本一致的 Python 环境，并安装 Playwright/Chrome 或以 `HUOHUO_PLAYWRIGHT` 指定其模块。默认使用 18814/18815，验证结束释放端口。`HUOHUO_RELEASE_CHECK_DIR` 仅允许复用具有本脚本标记且 tgz SHA 相同的自有验证目录；首次预览说明和已确认状态都要验证遮罩消失、委托查询与刷新可交互。不调用真实模型，也不替代全新 Python 安装验收。

## 研究成果交付（PAB-67）

用户可在对话中要求“把刚才的数据导出 Excel，附上来源”，或要求 CSV/JSON。`huohuo-deliverables` 指导格式选择；`create_research_file` 生成，`read_research_file` 核对及重新展示。原始数据按证据编号从本会话直接读取；模型整理单独标明。返回未知时用原 `source_call_id` 对账，不自动生成第二份。

成果归侧车 `huohuo/deliverables` 所有，存入实例 workspace 的 `.huohuo-deliverables`；各调用独立目录，原子发布、校验下载，不改业务数据库。主文件与交付说明 JSON 经 DSH 公开交付事件展示，下载动作使用持久事件坐标和既有认证通道。没有启用任意 present、shell 或文件工具。

CSV 为 UTF-8 BOM、单表；代码前导零及公式起始文本增加单引号，需无损原始值用 JSON/XLSX。Excel 支持六个数据表、冻结/筛选、单位与基础类型；不运行公式。每表最多四十列/五千行、总计五万单元格、每文件 10 MiB。生成目录首版不自动清理，用户需自行保留下载副本；来源说明包含原始记录，按研究内容同等保护。

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=sidecar:tests .venv/bin/python -m unittest test_deliverables test_deliverables_api -v
node --test lib/tests/deliverables.test.js lib/tests/capabilities.test.js
HUOHUO_PYTHON="$PWD/.venv/bin/python" HUOHUO_SMOKE_PORT=18930 HUOHUO_SMOKE_WEB_PORT=18931 HUOHUO_SMOKE_OUT="$PWD/artifacts/deliverables-uat" node scripts/smoke-skills.mjs --serve --deliverables
# 另一个终端，在同一 worktree；HUOHUO_PLAYWRIGHT 可指向已安装的 Playwright 模块。
node scripts/uat-deliverables.mjs
```

受控回放只接受“交付回放 CSV / JSON / Excel”。它验证真实 DSH、工具、侧车、文件与浏览器链路，不证明真实模型路由或真实来源质量。完整记录见 [设计与验收](研究成果交付设计与实施.md)。

## 数据与发布边界

本轮未改变 sidecar/schema。迁移、授权、租约、通知副作用变更需先定义兼容与恢复证据。不要复制旧实例、复活旧 attempt、自动重发 unknown 通知。关联 PAB-38（装配）、PAB-47（真实研究未闭环）、PAB-56（安装）；公开代码与产品许可由维护者决定，不因测试通过自动发布。

## 架构文档与图的维护

V1.4 的业务主图与当前运行装配分别维护。`docs/当前架构与装配.md` 中带 `diagram` 标记的 Mermaid 是五张展示图的唯一结构源；前两张必须与存档团队 Brief 一致。SVG 不再另行手写节点/边。

```sh
python3 scripts/render-architecture.py --check
# 只有改图时才需要渲染器：在独立工具目录安装固定 mermaid-cli 11.12.0，
# 设置 HUOHUO_MERMAID_CLI 为 mmdc 可执行文件；已有 Chrome 可用
# HUOHUO_PUPPETEER_CONFIG 指定含 executablePath 的本地 Puppeteer 配置。
python3 scripts/render-architecture.py
```

渲染器是文档工具，不加入产品依赖。生成后检查实际 SVG 的文字、箭头、分支与标签；`--check` 核验正文、提取的 Mermaid、SVG 指纹和主图基线。精选导出及 npm files 都应包含 `docs/设计基线`，移除个人路径不能成为移除业务基线的理由。

根目录 `SOURCE-MANIFEST.json` 保留初始导入时的来源指纹，不声称等于后续修改；每次 `npm run handoff` 会在新的导出目录生成对应当次内容的清单。不要用旧 ZIP/tgz 的校验和代表当前工作区。

能力维护检查：`npm run capabilities:check` 从 TypeScript 注册源核对聊天 Tool、Skill 文件、目录名称/数量及 README 入口；已纳入 `npm run check`。

## 服务器验证准备（2026-10-29）

风险偏好优化的本地候选按 PAB-55 追溯；证据见交付与验收。本轮先生成同一 npm 主包及 SHA256；包清单排除实例、数据库、凭据、缓存和测试夹具。包版本仍为1.0.0，因此服务器必须以候选包摘要区分内容，不能只看版本号。

尚需用户指定目标服务器、操作系统/CPU、新建隔离测试实例或更新既有实例、目录/端口及访问方式。获得本次目标和具体操作授权前不进行SSH、远程只读探测、上传、安装或重启。

建议先在服务器建立独立验证目录与空实例，通过同一候选tgz安装，保留127.0.0.1监听。默认使用SSH端口转发私密访问，认证入口来自服务器本次启动输出；如需公网域名/反向代理，另明确公开范围与TLS/认证配置。API不直接对外开放。模型凭据由使用者通过设置页面配置，不复制本地实例。

执行次序：核对平台及Node/Python要求→校验包SHA→安装独立实例→启动并获取本次认证入口→浏览器验证风险选择、期限、预览、保存/刷新和冲突→核对资料源/模型真实调用→记录服务器证据。新实例失败时只停止该验证进程并保留诊断；更新既有实例前需停止并完整备份，涉及schema回退不能只替换程序包。

当前状态是“本地候选和验证准备”，不代表Linux平台、远程部署、服务常驻或升级/回滚已验收。目标获确认后，再据实际环境给出路径和命令，不能把来源仓的Docker/1Panel部署直接套用到新仓。
