## 体验契约与能力映射

主任务：识别需要处理的事、查看新结果和提醒、确认仍在跟进的委托。主要操作进入原对话/原委托核对和处理；动态页不新增业务写命令。

| 用户动作 | 现有入口 | 状态所有者与副作用 | 缺口 | 决策 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 回答等待事项 | DSH session status / openConversation | DSH pendingInteraction；回原对话后原生确认 | 待办被历史淹没 | Compose | conversation-model、client 注入 |
| 补充或核对委托 | mandates / visit | sidecar 正式状态；动态仅导航 | 待补充与失败未突出 | Compose | followup、MandateView |
| 看研究结果与提醒 | mandates.executions / notifications | sidecar execution.result、联系决定与投递回执 | 表格平铺、渠道重复 | Compose | mandates.get、activity/model |
| 看正在跟进 | followupProgress | sidecar 运行与安排；不把配置当正在执行 | 与历史同权重 | Reuse | activity/followup.ts |
| 筛选与折叠历史 | React 本地状态 | 无业务写入 | 缺少阅读层级 | Extend | 现有 ActivityPage |
| 展示持仓变更动态 | 未找到此页统一事件接口 | 投资事实仍由原页面/Tool 持有 | 示例数据不能当能力 | 不纳入本轮 | 已核对现有动态读模型 |

长文展开复用现有 DetailPanel，属于纯展示交互，不新增 Tool、业务写操作或聊天能力。

全部分类、排序、状态、时间与数量由确定性模型生成；不调用模型摘要，不构造新的事件或持久化层。最新范围为最近 48 小时，旧变化与时间未知的记录进历史；读到的记录全部保留入口。多个渠道合并后仍保留各自的投递状态。

## 状态矩阵

| 状态 | 适用与呈现 |
| --- | --- |
| 加载 | 适用；各区域说明读取范围，不以零替代未知 |
| 刷新 | 适用；保留旧内容与布局，不卸载内容；可见刷新状态 |
| 空数据 | 适用；无待处理一行，暂无新变化与持续委托独立 |
| 筛选无结果 | 适用；保留筛选并可清除 |
| 部分成功/过期/错误 | 适用；区域独立反馈并保留旧记录，禁用不了解状态的待办处理入口 |
| 无权限 | 适用；明确认证/权限原因，不呈现普通空态 |
| 禁用 | 适用；加载中禁止重复刷新，待办资料过期时先刷新 |
| 成功 | 适用；原页面承担业务保存回执；动态仅呈现已保存事实 |
| 确认/撤销 | 不在此页新增；通过既有会话与委托入口完成 |

## 与批准示例的差异及集成边界

- HTML 示例只确认信息组织；按用户反馈，复用已有品牌、导航、DSH 主题与共享 Page / Controls，移除原候选中偏离产品风格的灰底、独立圆角卡片和方形控件。
- 不生成示例里的持仓变更动态、阶段百分比或研究未读数；首版筛选为全部/研究结果/提醒，联系渠道按同一决定合并后保留不同回执。
- 研究结果可定位到确切 execution；提醒沿用确切 decision 回访。待回答操作回原 DSH 对话，动态不提供第二套批准/撤销系统。
- 最新范围明确为 48 小时；较早、未知或异常未来时间的已读取记录留在历史。已知分页未读全时不报告全量零项。
- 依赖基线 ac9ed0f 的委托进展代码；不纳入其他 worktree 的未提交全局提醒/刷新改动。集成时须先处理基线依赖，不能直接默认与当前 main 完全独立。
- 回退可在后续集成时撤销本任务的 UI 增量；无数据库迁移、授权变更或新外部副作用。
