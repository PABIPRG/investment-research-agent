# 策略验证与演进

设计基准 V1.4。策略记录由当前实例侧车保存；DSH 负责理解、提出研究假设、调用工具和解释。
设置中的注册状态只说明产品已装配，真实行情是否可读以本次调用回执为准。

## 从页面开始

1. 打开顶部「验证与演进」，选择「新增策略」。填写名称、证券、验证规则和研究假设；预览后确认保存。
2. 对候选运行回测，确认日期范围。固定以 70% / 30% 分为样本内外；每次请求限 1–3 只沪深 A 股、40–1095 个自然日。
3. 查看记录，区分参与状态与验证分类：一次有效回测完成后可参与验证，但不代表样本外达标。资料不足、未达标和采集失败分别显示。
4. 用「更新影子验证」保存当前最新已完成日线的模拟结果。第一次从当前真实跟踪日期开始，不把旧回测曲线当作已经持续跟踪的历史。
5. 积累至少 5 个有效影子日期后，生成单策略或「全池预案」。全池范围支持同批比较、相关性治理、双亲重组等旧算法。
6. 查看精确动作后确认应用。程序核验版本与时效，原子保存动作、子代、存档和回执；新候选仍需重新回测。取消、关闭确认或自由回答都不提交。

本版默认只按明确请求运行，没有自动开启旧后台定时任务。你也可以在「验证与演进 → 设置后台计划」选择策略、验证动作与时间，经预览确认后持续执行；新策略不会自动加入范围，候选与应用预案仍另行确认。关闭聊天不会撤销已经接受的单次计算；
运行时可从页面停止本次计算，迟到结果不会写入策略。重启中断单独记录，需要核对后明确发起新运行。

## 从设置或对话开始

打开「设置 → 工具与 Skill」，搜索策略。展开能力后：

- 「在新对话中使用」通过 DSH 原生机制准备草稿，由用户补充并发送。
- 「管理策略与验证记录」进入正式页面，不启动计算。

| 工具或 Skill | 作用 |
| --- | --- |
| `huohuo-strategies` | 研究方法、输入澄清、原生确认与结果边界 |
| `read_strategy_records` | 当前策略及版本、运行回执、来源和 OOS 先验；可按策略或请求标识精确核对 |
| `manage_strategy` | 保存、回测、影子验证、生成/应用预案和停止；先预览，再等真实原生回答 |
| `strategy_pool_lookup` | 当前实例策略池阶段、影子天数和程序判定 |
| `strategy_attribution_lookup` | 虚拟资金影子组合及各策略的收益、回撤、平仓模拟归因 |
| `strategy_evolution_preview` | 只读取已经保存的当前预案，不生成、不应用 |

DSH 可以提出候选规则，不能自行填写收益、验证结论、身份或确认回答。
`source_evidence_ids` 只能引用当前用户及会话已经留存的有效研究工具证据；
无外部证据时，明确保存为用户确认的研究假设，不冒称来自事件披露。
历史样本外先验来自已保存的程序验证分类；样本不足不计为通过。

## 模拟与失败的含义

- 仅做多、虚拟资金、允许分数股，不计费用、滑点和涨跌停成交限制，不等于实际可执行收益。
- 信号使用截至当日资料，下一根日线开盘执行。回测末尾强平；持续影子不在末尾强平。
- 组合按日期对齐，只沿用更早已观察的权益，不把未来价格填入过去。归因收益相对于初始本金。
- 任一所需证券行情失败、截止不齐或过期，本次不写正式收益，保留失败原因；不把缺数据模拟为持有现金的稳定收益。
- 基准不可用时按未知政策处理，不能暗用旧市场分类；冬眠保留本次环境依据和跳过回执，不写净值或成交。
- 提交连接中断不代表未接受；先刷新或按回执中的 `request_key` 查询，不更换标识自动重放。
- 旧用户策略与影子数据没有自动导入。代码迁移不构成读取其他实例或连接旧服务器的权限。

## 维护与验证入口

- 策略领域：`sidecar/huohuo/strategies/`；实例迁移：`010_strategies.sql`。
- 旧纯算法的对应来源与摘要：`legacy/provenance.json`。新策略规则不得另建模型侧计算体系。
- DSH 入口：`product/chat/strategy-tools.ts`、允许名单及自带 Skill；三个研究工具继续复用原有名称。
- 设置目录由实际注册和允许名单投影；注册变化后生成研究契约并执行相关检查，不能仅修改目录文案。
- 聚焦检查：`test_strategy_domain`、`test_strategy_algorithms`、`test_strategy_api`、`strategy-tools.test`、`capabilities.test`。
- `tests/strategy_ui_server.py` 只供隔离 UI 验收，使用合成行情与推进的测试时钟；不进入运行发行包，不作为真实市场证据。

后台计划与持续委托共用任务和执行机制，停止计划会撤销排队和在途执行；已有验证记录保留。升级时未知的在途工作标记中断，不会自动重做。
