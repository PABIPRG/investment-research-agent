## 已落地的组织方式

- `shell/`：产品外壳、账户、入场、IP、历史；`Shell.tsx` 仅安装适配。
- `investment/`：四类列表、证券选择、编辑草稿、两步确认与领域读取。
- `mandates/`：列表、详情、约定编辑、证据、状态读取与命令。
- `notifications/`：渠道字段、独立编辑器、草稿与提交映射。
- `research/`：单次研究列表、详情与证据；`shared/` 统一 API 错误处理。
- DSH 保留会话、消息、轨迹、输入与凭据所有权；拆分未新增平行状态库。

`npm run check` 包含 `check:ui`：遍历 `product/ui` 中所有手写 TS/TSX/CSS/JS，检查 Prettier 格式及单文件不超过 300 行，仅第三方 vendor 排除。`npm run format:ui` 统一格式化。新增或继续修改组件时按职责拆分，不以压缩行数满足门禁。当前 71 个文件，最长 229 行；页面入口分别为 Shell 59、client 106、持仓 121、委托 44、提醒 159 行。

完成状态仅表示本轮细节整改、拆分与受控浏览器验证；行情/收益与框架/演进的正式能力缺口仍未关闭。


## 工具与 Skill 设置方案（2026-10-27）

用户在 18841 要求聊天记录成交，但收到当前只有只读工具的说明。核查当前 UI worktree 的 `product/chat/investment-tools.ts`、投资 Skill 与守卫，以及 `ResearchToolBridge.run`，确认该实例只有 read_investment_facts；portfolio_lookup 等需授权研究工具被明确阻断。独立能力提交 e172442 已实现聊天预览、原生确认与提交，但未进入当前 UI 基线。未在本轮擅自整合分支、切换用户实例业务版本或解除授权。

| 用户动作 | 现有入口/接口 | 状态所有者与副作用 | 缺口 | 决策 | 证据与待验证 |
|---|---|---|---|---|---|
| 读取投资记录 | read_investment_facts、GET /investment | sidecar 投资事实；只读 | 当前实例未录入，不能当作空仓 | Reuse | 当前注册代码及页面均存在 |
| 聊天记录/更正成交 | 页面 preview/commit；独立提交 e172442 的聊天业务工具 | sidecar 预览/确认/版本/幂等；真实写入 | 当前 UI 版本未整合聊天写入工具 | Compose | 先评审与整合能力版本，再验证原生确认与取消/冲突/未知提交；不能只改 Skill 文案 |
| 查工具及 Skill 状态 | DSH tools/skills 注册与守卫；当前 3 个产品 Skill | DSH 工具/Skill 基础，产品允许名单 | 设置无状态目录 | Extend | 沿用已安装 rc2 的 settings.section，服务端投影实际注册与限制；不用手写运行时目录冒充可用性 |
| 配置来源/凭据 | 原生模型设置、产品提醒表单；研究授权尚有缺口 | 各配置 owner 与程序权限 | 部分能力没有真实配置入口 | Reuse | 仅对已有入口显示“去配置”；未接入项说明原因，不显示可切换授权按钮 |
| 安装或启停 Skill/Tool | 产品 Bundle 禁用了通用插件管理和默认文件扫描 | DSH 装配、产品允许名单与权限 | 无产品级管理契约 | Extend | 后续确认使用范围、持久化、守卫一致性和运行中会话行为；不直接开放任意插件、路径、命令或新权限 |

建议在现有设置导航新增“工具与 Skill”，默认用紧凑列表，搜索 + Tool/Skill 筛选，不用大卡片。每行显示中文名称、用途、来源、当前状态、必要操作；点开详情才显示内部名称、依赖、限制和最近错误。Skill 标明它组织哪些已允许工具；加载 Skill 不授予工具权限。状态至少区分“已注册 / 可调用”“待配置”“受限制”“本版本未接入”，来源健康必须有实际检查证据，不能把已注册显示成始终可用。密钥只在原有受控表单中填写。

程序提供注册、允许名单、配置、权限与检查状态；模型仅解释用途及调用方法。下一步是将能力分支与 UI 分支做串行整合评审，再实施设置只读目录；启停、安装及授权操作在各 owner 的真实接口与安全契约齐备后增加。前轮为候选方案；本轮用户确认后已实施设置只读目录，见 UI 设计与验收记录。启停、安装、授权和聊天写入整合仍未实施。
