# 委托 Hook 前置与模型调用门禁设计

日期：2026-10-29。状态：用户已确认，第一阶段统一门禁已实施。本文保留完整目标设计，不代表所有阶段均已实现；当前实现、未覆盖项及验证证据见[实施与验收](V1.4-委托Hook统一门禁实施与验收.md)。

## 目标与约束

用户要求后续委托先命中程序化 Hook，再按需要调用模型；无论什么情况都走一次模型不符合产品约定。成功标准是：每次后台模型研究都能关联到有效委托、可信触发事件、已登记规则和程序做出的准入决定；没有准入决定就不能开始模型调用。

本设计承接 [V1.4 的 Hook 契约](V1.4-产品与架构设计.md#56-委托触发时机与-hook-契约)和[程序化 Hook 概念说明](../概念/程序化Hook与研究触发.md)，不替换委托核心、事件设施、任务队列、租约或通知系统。

项目追溯关联现有 [PAB-48 资料变化发现与事件路由](https://linear.app/pabiprg/issue/PAB-48/100huohuo-v14-08-资料变化发现与事件路由)和 [PAB-49 持续复核与联系决定](https://linear.app/pabiprg/issue/PAB-49/100huohuo-v14-09-持续复核与联系决定)。两项在本次读取时均为 In Progress；本设计不改变其验收结论，也不新建外部事项。

## 方案比较与选择

| 方案 | 效果与限制 | 选择 |
|---|---|---|
| 在提示词中要求模型自行决定是否需要研究 | 模型已经被调用，无法阻止成本产生；规则由模型解释，缺少强制边界 | 不采用 |
| 只给每个数值条件逐个增加绕过模型的分支 | 可解决局部成本，但遗漏路径仍默认进入模型；未来新增任务容易绕过限制 | 作为程序执行能力复用，不能单独作为最终方案 |
| 核心统一决定是否执行以及执行方式，模型入口再次核验 | 复用原有状态与任务设施，同时约束普通研究、数值检查和策略候选 | 推荐，待确认 |

## 程序与模型的边界

程序负责事件身份、来源版本、对象匹配、权限、委托版本、取消代次、数据时效与单位、数值计算、条件转换、限频、额度预占、幂等、任务创建和发送资格。模型负责有范围的语义相关性判断、跨材料推理和解释。

触发规则与联系规则分开保存。触发规则回答何时执行哪种工作，联系规则回答什么结果可以联系用户。不能把历史联系阈值静默解释成新的模型研究授权，也不能让模型补出立即生效的触发阈值或授权范围。

### 准入结果

| 结果 | 处理 | 是否调用模型 |
|---|---|---|
| 本次无需处理 | 保存检查或事件处理原因，不登记本次模型研究 | 否 |
| 等待资料 | 保留 unknown、依赖和等待原因，不当作条件不满足 | 否 |
| 程序执行 | 运行确定性取数、计算、规则评估或直接提醒 | 否 |
| 允许模型研究 | 可信事件与规则命中，资格有效，研究频率和调用额度允许 | 是，只运行本次有界任务 |
| 配置或执行受阻 | 规则不受支持、来源未接通、权限失效或处理故障，分别记录 | 否 |

这些是准入决定，不直接新增第二套任务终态。存储优先扩展既有委托版本、任务 checkpoint 和业务审计接口；实现前须核实无任务情况下的检查记录如何持久保存，不能伪造“研究成功”或依赖非持久日志。

## 处理路径

1. 可信来源或日程服务保存事件，原子完成快照、版本和事件交接。
2. 核心按主体、范围、依赖和有效版本匹配委托，排除重复或已被替代的事件。
3. 前置评估器读取当前正式规则与绑定资料，生成上述准入决定。可计算条件在这里完成；不满足时终止本次模型路径。
4. 需要执行时才登记原有任务，并持久保存准入依据。领取任务不授予新的研究权限。
5. worker 启动 DSH 和发送 prompt 前，由侧车核验当前 attempt、租约、委托版本、取消代次、事件与准入决定；缺失或无法核验时不调用模型。worker 不能仅凭本地 JSON 中的 `allow_model` 布尔值放行。
6. 计算或研究结果进入原有证据校验、联系决定和通知链。迟到结果可以留档，不能恢复失效资格。

准入依据至少绑定委托 ID、修订号、取消代次、任务与 attempt、事件 ID 与来源版本、触发规则版本、决定原因及有效期限。不能跨用户、委托、版本或 attempt 复用。

模型提交是外部动作，不能靠数据库事务保证与暂停瞬间绝对原子。提交前再次核验并在控制变化时取消；已经发送或响应丢失的请求按不确定执行对账，不自动重放。验收须区分“提交前阻止”和“提交后取消或隔离”。

### 不同任务如何准入

| 任务 | 合法触发与执行方式 |
|---|---|
| 纯数值提醒 | 用合格来源值计算规则，按约记录状态与联系；整个过程可不使用模型 |
| 数值命中后进一步研究 | 必须有明确的触发阈值及后续研究约定；命中且符合研究限频后才允许模型 |
| 财报公告等语义研究 | 先有授权范围内、有效且未处理的新资料；语义结论由后续模型研究给出，不要求前置程序提前知道结论 |
| 混合条件 | 明确区分触发条件与联系条件，保持 all/any 逻辑；不能把 OR 分支错误转换成所有数值必须命中，也不能把缺失指标当成通过 |
| 初次研究 | 创建事件只有在该委托需要且已授权初始研究时才准入；纯提醒和不需要比较基准的规则不默认跑模型 |
| 单次人工复核 | 必须来自可信的明确请求入口；不能把目前用于待补充流程的同名事件直接当作人工研究授权 |
| 定时成果交付 | 以当前日程的真实到期实例准入；不能因为资料没有变化跳过已约定的交付，也不能未到期先跑一次模型 |
| 周期检查 | 到期只表示应检查，再由程序决定是否需要模型；检查不自动等于完整研究 |
| 策略候选 | 沿用策略来源和计划限制，候选模型入口也验证准入；回测等确定性任务仍走程序 |
| 当场研究 | 保留已授权的当场研究路径，明确区别于后台持续委托；不得允许客户端伪装“人工请求”绕过后台限制 |

## 未接通 Hook 的处理

先完成统一准入与当前已有来源的覆盖，再按正式来源和对象契约补齐其余事件。每种未接通 Hook 必须保留具体缺口，不能把“允许登记事件名”作为完成。

| Hook 家族 | 后续接线要求 |
|---|---|
| `market.condition_changed`、`risk.condition_changed` | 保存业务条件状态与转换；区分首次进入、再次进入、持续成立、unknown 和故障。报价变化与条件命中分别记录 |
| `company.event_available` | 接通公司事件的正式来源、稳定公司标识、资料版本和更正关系，匹配依赖它的委托 |
| `news.item_available`、`industry.event_available` | 按条目、实体、主题和问题依赖路由，合并转载关联；语义筛选本身也必须有调用限制 |
| `evidence.revised`、`data.dependency_available` | 绑定原证据和等待依赖，定向唤醒；资料归档或服务恢复不能全量启动委托 |
| `entity.reference_changed`、`user.preference_revised` | 由身份或用户偏好领域产生正式修订，只重验受影响依赖，不扩大授权 |

本设计确认不代表以上全部来源同时具备运行条件。未接通或没有明确执行规则的部分，显示受阻或未启用，不回退到默认模型研究。

## 频率和成本约束

研究频率与通知冷却分别记录和执行。模型任务使用窗口内允许调用次数、并发与重试额度，并在准入时由程序预占，重复事件与并发 worker 不能重复领取额度。额度的作用域、窗口和上限必须来自明确配置，不能由模型自行填写；配置缺失不能按无限额处理。

调用次数上限不是 token 或金额的硬上限。本轮不宣称实现统一金额预算；若实现 token 硬限制，还需验证所用 DSH 与 provider 的输入、输出和用量回执接口。调用结果未知时，已预占额度不能直接释放后重试。

## 兼容与迁移

- 新委托保存可执行触发约定与执行方式，和联系策略分别校验；不支持的配置在启用前暴露。
- 已有明确规则且语义可等价转换的委托可生成兼容投影，保留原版本与来源。不能可靠推导触发方式或研究限制的旧委托先标为需确认，不静默扩大授权或继续默认调用模型。
- 旧队列任务在领取及模型提交前重新校验，不能因创建于升级之前获得豁免；在途提交按已知、未知和完成状态分别对账，不重放。
- 持仓风险与普通价格候选路径存在语义重叠，功能实现从新鲜默认分支创建独立 worktree；不搬入另一工作区的未知修改。集成前重新核对两边最新状态。
- 若需要新增持久字段、决定记录或额度账本，使用原有迁移机制并补迁移验证；不建立独立调度器、队列或数据库。

## 分步实施与验证

| 步骤 | 交付 | 必须先失败的关键证据 | 完成检查 |
|---|---|---|---|
| 1 | 定义独立触发约定、执行方式及准入契约 | 缺规则或伪造准入的后台任务仍能进入模型 | 契约校验、旧规则兼容与拒绝分支测试 |
| 2 | 复用正式指标与计算，覆盖已有数值检查 | 未到阈值仍创建模型研究；缺失或过期值误放行 | 纯数值、混合逻辑、状态转换和资料未知测试 |
| 3 | 核心路由、普通 worker 与策略 worker 接入门禁 | 省略标记、旧版本、过期租约或错误主体可触发 DSH | HTTP 与 worker 测试，直接断言 DSH 初始化和 prompt 次数 |
| 4 | 限频额度、幂等与恢复 | 重复事件或并发请求导致重复模型调用；未知提交自动重放 | 事务并发、崩溃恢复、额度占用和重复投递测试 |
| 5 | 用户认知与真实入口验证 | 页面把检查当研究，或保存成功就显示未接通能力已启用 | 合成来源与受控模型下的真实入口验收，更新概念文档 |

端到端验收至少覆盖：未命中数值条件时模型调用为 0；命中纯提醒时为 0；命中明确研究约定时按约调用；重复报价和同状态事件不重复研究；合法新资料触发一次语义研究；资料缺失或过时不放行；暂停或改约后旧任务不放行；定时交付未到期为 0、到期按约运行；直接提醒为 0；策略候选遵守同样准入；升级前积压任务不能绕过门禁。

本地使用合成资料、隔离数据库和受控模型，不调用真实付费模型、不发送真实通知、不操作服务器。验证端口与实例在功能 worktree 创建后单独分配，不占用用户常驻服务。真实模型成本、真实外发和长期运行另记验证状态，不用受控通过替代。

## 回退与交付边界

开发改动在独立特性 worktree 内完成，不直接修改默认分支。本设计和现有知识库文档保持可独立审阅；提交、推送、PR、合并和发布继续按各自授权处理。

出现门禁或迁移故障时，暂停受影响的后台模型任务，保留事件、任务、检查决定和在途状态。不能以“回退”为由恢复无条件模型调用；任何旧版本恢复都必须先隔离不能识别的新规则与任务。数据迁移回退方案根据最终字段设计确定，并在写入迁移前验证。

## 已确认的设计决定

确认推荐方案：在现有委托核心与所有后台模型入口实行统一、默认不放行的准入门禁，先覆盖当前已有来源及数值规则；其余 Hook 按正式来源逐类补齐，未接通部分保持可见的受阻状态。首次必要研究、明确单次复核和定时交付按各自合法触发准入，不作为绕过门禁的通用例外。

本方案已获用户确认，并在独立功能 worktree 实施第一阶段门禁。完整业务 Hook、独立研究触发配置及统一 token/金额硬上限继续按阶段推进，不因第一阶段通过而计为全部完成。设计、分支和验证证据继续关联既有 PAB-48/PAB-49，项目状态不由本地提交自动更新。
