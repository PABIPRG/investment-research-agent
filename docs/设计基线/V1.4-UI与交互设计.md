## 体验契约

用户先认出火火，再看清待办或当前情况；开始交谈后，内容成为主体。顶部导航独立分层；账户汇总收进首页迎接区右上角的紧凑信息块，左侧为待办与提问入口，右侧为放大的火火。对话只存在于对话模块，历史使用浮窗。快捷按钮与自由输入同时保留；任意表达交给 DSH，不做本地关键词回复。

参考方向取舍：Tiimo 的任务优先级、Ebb 的角色与交流关系、多邻国的角色反馈；不照搬其模块或品牌风格。使用既有 Blender 火火 IP，不替换形象。纯色为主、无模块左侧色条；按钮胶囊、信息区域直角，数据列表保持密度。默认采用已批准稿当前云蓝配色；六套比较配色保留在设计稿，不把设计选择器带入产品。

## 能力复用与差异

| 动作 | 状态所有者 / 接口 | 决策与接入 |
|---|---|---|
| 新建、打开历史 | DSH uiWorkspace / sessions | 复用；历史只是 DSH 目录的过滤投影，使用模态浮窗 |
| 输入、附件、队列、停止 | DSH conversation.content / InputActions | 组合原生组件；不另存消息或草稿 |
| 轨迹、工具详情 | DSH conversation.session 的 view=trajectory | 直接呈现原生视图，保留真实事件和局部检查器；不启用工作区或更改开发工具权限 |
| 用户问题与确认 | DSH conversation.composer / pendingInteraction | 原生接管输入；IP 进入等待回答动作 |
| 委托、暂停、恢复、修订 | sidecar mandates 与既有桥 | 复用幂等命令；主视图按 r1 改为六列表格，详情与修改进入浮窗 |
| 持仓、自选、成交、更正 | sidecar investment | 复用正式预览/提交；八列持仓、四类记录入口、研究关联；账户突出市值/盈亏/已记录成本并支持隐藏。行情与日收益基准缺失时显示“—” |
| 提醒方式 | sidecar notification-config | 复用原有保存与确认，不发送真实通知 |
| 动态 | notifications 已保存回执 | 按 r1 四列表格组合列表与原委托回访，不生成新决定 |
| 我的框架、验证与演进 | 新仓缺少正式页面 API | 按 r1 五列表格保留信息结构并明确未接入；不把旧版或演示数据冒充产品结果 |

DSH 版本固定 0.2.1-rc.2，适配面集中在 dsh-face.ts；产品占用 sidebar/main.conversation 插槽，保留 DSH 原生 frame 与完整 conversation.content，负责对话内部状态。sidebar 内容通过布局样式放到顶部；轨迹显式视图选择避免依赖工作区 UI。

布局适配使用该固定 DSH 版本的 frame/sidebarCol/centerCol、composer card 与原生问题面板样式类；升级 DSH 必须重验顶部导航、原生问题和轨迹。头像使用当前轮原生 data-chat-flow-kind=turn-process 的稳定起点；缺失时退到本轮首条回复/用户消息，交互问题使用 data-question-key。不得追逐最后一个流式片段、时间或操作栏。产品动作命名为 openHistory，避免与原生会话传入的 open 属性冲突。

## 子模块实施对齐规则

- 所有证券标题优先使用委托确认名称或投资事实中记录的名称，代码作为辅助文字；没有可靠名称时显示“名称待补充”，不建立猜测映射。
- 业务列表使用紧凑表格；详情按需打开模态浮窗，不自动选第一行占用半页。浮窗支持 Escape、关闭和返回触发按钮的焦点。
- 持仓提供持仓、自选、操作记录、修订历史；校正与成交保持独立。数量与成本来自已保存事实；现价、市值、浮盈缺行情时保持未知。
- 账户汇总块只在首页迎接态显示；进入实际对话或其他业务页后让出空间。账户隐藏偏好本地保存并在刷新后保留。该开关作用于首页账户金额，不代表隐藏持仓编辑页面的全部记录。
- 模型提供商及凭据仍由 DSH 原生设置管理。`smoke:skills -- --serve` 禁用真实提供商，页面和模型设置显示受控说明；正常产品配置的原生 API Key 表单已单独验证。
- 单次研究标题剥离后端追加且结构可识别的研究上下文；原始任务与证据继续保存在正式状态中，普通用户文字不受影响。

## IP 状态与资源

使用已有 huohuo-animated.glb（12 个动作）与本地 Three.js 资源；无 CDN。idle 对应空闲，listening 对应草稿，thinking 对应运行，speaking 对应可见流式回复，awaiting_reply 对应原生待回答问题。动作只反映已观察到的状态，不宣称后台研究已完成。

入场大形象，开始会话后缩为侧边头像；问题出现时转入等待回答位置。退到一旁时卸载渲染器并回收空间。后台标签暂停帧循环，减少动态效果时静帧呈现，WebGL/资源失败时保留同 IP 静态图，聊天继续。产品不使用动画完成作为业务成功信号。

## 状态与验收范围

| 状态 | 适用与处理 |
|---|---|
| 加载 / 刷新 | 历史、账户、业务列表各自显示状态；刷新不清空已读数据 |
| 空数据 / 筛选空 | 保留原生历史与业务空态，区分未录入和已确认空仓 |
| 过期 / 错误 / 无权限 | 保留业务原页反馈；历史显示连接失败与重连，账户失败不显示零 |
| 禁用 | 输入提交由 DSH 控制；草稿非空时快捷按钮禁用以免覆盖 |
| 确认 / 成功 / 撤销 | 投资事实沿用预览确认、事实版本和更正；提醒保存原确认不变 |
| 部分成功 | UI 不创造跨域复合写入，既有领域返回值继续展示 |
| 模型 / 原生问题 | 真实 DSH 组件；验证环境模型为受控夹具，不是实盘研究 |

支持 1440 / 1024 / 768 / 390px。窄屏顶部导航横向滚动、账户缩减辅助文字、表格区域横向滚动；深色跟随 DSH 的主题选择。验收结果单列，构建成功不能代替浏览器通过。

实施与验证证据见 [V1.4 UI 验收记录](V1.4-UI验收记录.md)。

## 可读内容与证据回访

- 复核记录先说明判断、理由、时间和提醒处理，再提供“查看本次依据”。依据呈现资料名称、报告期、来源、采集时间、可用内容及限制，允许打开来源。
- 研究记录先显示保存的具体判断及理由，而非只显示执行完成；展开后能看该次摘要与引用资料，明确哪份是后续比较的参照。
- 资料通过既有决定/任务/结果中的明确标识关联，不按时间接近或列表位置猜测。关联缺失或歧义明确说明，过期结果不补成当前理由。
- 内部编号仅放入默认收起的“排查信息（可选）”；面向用户的名称、内容和操作不能由编号、哈希或 JSON 替代。
- 成交修订用字段前后值对照；撤销记录明确表示撤销，不能把空的修订值当成字段归零。
- 继续复用已保存研究内容，不重写或补造投资结论。受控实例中的合成说明必须保留。

依据用户本轮反馈，取消横贯顶部的账户条，三项金额、隐藏开关和持仓入口合并为迎接区右上角信息块。缺行情、缺收益基准仍保留说明，未录入不显示零或暗示已完成投资记录。对话外层间距收至 8px，取消 1160px 最大宽度；输入框最大宽度同步放宽。左侧文字与操作、右侧放大的已有动画 IP；开始聊天后仍转为侧边头像，历史和轨迹继续由 DSH 提供。窄屏账户块在上，文字与 IP 分列。r1 归档原稿保持不变，本轮属于实现改稿，尚待用户确认。

## 首页连续交流区域调整（2026-10-27）

用户基于上一轮实际截图要求重新组织整体构图。本轮将会话视图、状态和操作合为一条工具栏；首页取消迎接区与输入区的横向色块切割，两者共享画布和对齐宽度。待办/欢迎内容在左，动画火火靠近内容右侧，账户独立置于画布右上角。输入框紧接迎接内容，让阅读和继续提问构成一段过程。

迎接态 IP 的纵向位置按实际 Arrival 容器计算，账户高度变化会推动迎接内容下移；移动账户进入正常文档流。空闲与聆听仍使用既有模型动作，active/pending 继续以原生回答/问题定位。短窗口迎接内容允许在会话正文内部滚动，不能为保留完整 IP 或账户而裁掉输入框。当前安装版本的原生输入容器宽度适配仍集中于 shell CSS，不接管 DSH 消息、草稿、轨迹或历史状态。

本轮截图属于待用户确认的实现迭代；原 r1 静态交互稿保持不变。账户仍沿用上一轮的迎接态可见规则，未扩展为聊天中的常驻资产面板。

## 会话状态与新动态提示（2026-10-27）

- 空会话不显示视图切换；DSH 公开 useTrajectory 投影出现事件、请求、实时片段、调用或系统提示内容后才显示“对话 / 轨迹”。会话切换回空投影时自动回到对话。删除无状态信息的“与火火一起看”，运行时仅展示真实处理状态。
- 失败通过 DSH 正式 conversation.chat.node 的 turn-error renderer 呈现：中文原因、明确恢复路径、默认收起的原始错误。缺凭据以“发送这条问题时”表述，不能把历史失败当成当前配置状态。仍在原生设置表单处理 API Key；当前公开装配没有通用直达模型页服务，因此使用可展开的准确配置步骤，不伪造“已打开设置”动作。
- 空执行过程不重复出现“处理失败”；有内容的过程保留 DSH owner 的展开状态。只有 aborted / interrupted / error 强制展开，blocked / max-tokens / forked 等可折叠终止状态仍保留展开入口。回复与输入列对齐；活跃 IP 贴近当前回复/失败卡片，展开详情或过程后重新定位。
- 动态角标是“本机新动态”，不是正式待办或跨设备未读。复用只读 notifications 列表，同一 decision 的多个渠道只计一次；实际状态版本变化再次提示。成功加载并显示动态与相关委托后记录本机已看版本，失败或只点击导航不得清零。0 不显示，超过 99 显示 99+；每 30 秒和窗口重新聚焦刷新。
- 已看版本只保存在当前 origin 的 localStorage，最多保留 1000 个决定；列表读取受后台最近 200 条渠道记录窗口限制。跨浏览器/跨设备不共享；存储不可用时仅在当前页内保留。不新增后台已读字段，不改变联系决定、投递或通知资格。

## 加载停靠稳定性与输入区边界（2026-10-27）

加载中不再从最后一个流式片段、错误、回复和过程节点中反复选目标。定位逻辑独立为 useCompanionDock 与 dock-model：按当前轮选择同一个原生 turn-process 起点，零高度时仍是合法占位；同轮后续步骤和完成状态不改变目标，新轮才换起点。没有几何锚点时先隐藏停靠容器，避免短暂出现在旧位置或页面角落。

只有迎接/头像/交互问题三种空间模式切换时启用一次 480ms 位移过渡；正常流式更新、滚动和展开过程不使用 left/top 过渡。继续使用同一个动画 IP 容器，思考、说话等动作仍反映真实状态。滚动时位置直接跟随并限制在消息可视范围，避开输入栏。

native 容器与整个对话正文等宽，取消 76/112/45px 的整体左缩进；头像空间只预留在消息列中。输入栏外层使用正文相同纯色背景，不继承 DSH 原生渐变；内层输入卡维持阅读宽度，外层背景和左边界贯通。浏览器滚动条保留正常占位，不能通过扩大整个 native 容器挤出横向滚动。

## 轨迹阅读模式（2026-10-27）

轨迹视图隐藏原生 composer-seat（输入框、附件/发送操作及底部统计），将空间留给时间线、记录与详情。输入组件和草稿继续由 DSH 保持，切回对话后恢复，不能通过卸载输入 owner 清空草稿。轨迹中没有 IP，因此同时隐藏“退到一旁/叫回火火”；新对话、历史和返回对话入口继续保留。运行中的会话仍显示真实状态，需要发送、回答或停止时切回对话处理。


## 跨模块一致性与信息权重（2026-10-27）

本轮将页面表面、边框、业务标题和控件尺寸提取至 `product/ui/shared/Page.module.css`。对话、委托、动态、持仓、框架、验证和提醒共用同一主表面 token；浅色均为白色，深色共用对应深色表面。浅蓝只用于选中态、用户消息、表头和账户/失败等局部辅助区域，不再作为整个对话画布。页面只有一层边框，不叠加宿主边框。

一致性不要求每个模块有相同的大标题或相同留白。业务页标题用于说明任务及数据范围；对话已经由主导航和消息内容说明上下文，因此不显示重复的“与火火的对话”大标题，仅保留无障碍标题和紧凑的视图/历史工具栏。画面优先级是当前问题与回答、必要操作、辅助状态；运行状态只在真实运行时出现。迎接态主角仍是当前待办和已有动画 IP，未开始聊天时不虚构轨迹入口。

输入卡使用主表面、细边框和大圆角，移除悬浮阴影；输入外层与对话正文同色。对话与业务操作使用相同的控件尺寸变量，窄屏保证 40px 点击高度。复用 DSH 的输入、草稿、历史、轨迹和主题状态，消息执行逻辑不变。原 r1 交互稿保持归档，本节是待用户复核的实现迭代。


## 头像动作可辨识性（2026-10-27）

聊天停靠头像由桌面 56×66 调整为 96×112px，手机由 42×52 调整为 64×76px；这是 canvas 容器尺寸，GLB 保留动画所需的透明范围。迎接态的大 IP 保持原尺寸。问题态随之调整为桌面 112×128、手机 72×88px。消息列为头像局部留出 108/76px，输入区仍贯通正文，不扩大整页边距。

尺寸由 CSS 自定义属性统一提供，停靠定位读取同一目标尺寸，避免 CSS 与定位逻辑各自维护一份数值，或读取转场中的临时宽高导致抖动。继续保留同轮固定起点、空间模式转场及 reduced-motion 行为。


## 设置：工具与 Skill（2026-10-27）

使用 DSH 正式 settings.section，在通用设置、模型后加入“工具与 Skill”。现阶段为产品装配目录：搜索中文名称/用途/内部名称、按 Tool/Skill 和注册/限制/待接入筛选；紧凑行显示名称、用途、类型与状态，展开后才显示完整说明、来源、内部名称和限制。投资记录项可关闭设置并前往现有投资记录页。没有安装、启停或授权写操作。

目录通过 DSH 已认证 transport 的只读 /api/huohuo/capabilities 返回；服务端复用当前安装版本的 createChatTools、实体确认工具工厂、nativeChatToolNames、allowedChatToolNames、chatSkillNames 和自带 Skill 文件。它表示本版本产品 preset 装配，不冒充当前会话实时工具探测；读取不创建会话、不执行工具、不读取模型凭据、不探测外部数据源。研究元数据的中文名称、分类与授权限制从 Python 注册契约生成，与实际限制共源。

“已注册”只表示已进入该产品装配和允许名单，不保证远端来源健康；“受限制”表示独立实例授权流程尚未接入，不提供虚假开关；“待接入”表示当前隔离实例缺少所需服务/来源。来源状态仍以真实调用回执为准。密钥继续在原生模型与现有渠道表单中配置。Skill 说明工作方法，不授予工具权限。
