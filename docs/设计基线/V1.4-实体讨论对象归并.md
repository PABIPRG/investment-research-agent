# 实体讨论对象归并

追溯：[PAB-42](https://linear.app/pabiprg/issue/PAB-42)。工作区 codex/account-valuation，基准 2c8a4bc；本轮只修改实体解析、确认、研究范围及相关契约/验证，保留先前未提交工作。

## 能力审计与实施边界

| 用户动作 | 现有入口 | 状态所有者与副作用 | 缺口 | 决策 | 证据 |
|---|---|---|---|---|---|
| 名称和代码讨论同一对象 | resolve_research_scope | 侧车实体目录、原文 mentions | 两处提及生成两题、两条 Scope | Extend | resolution.py、scope_builder.py |

确定性身份、归并、快照版本、回执与权限由程序持有；模型只提取原文、理解问题和组织解释，不生成实体 ID 或确认记录。

## 计划与兼容

1. 先增加失败回归，再按相同 resolved_entity_id 构造讨论对象；不把公司与证券永久合为一个 ID，不用候选交集推定等价。相邻名称/代码冲突生成一题澄清；显式区分公司与股票时保留两个身份。
2. Scope 按对象组构造一条条目，保留成员 mention_ids。确认 Tool 按组生成原生题，显示标准名称与代码，不展开为两道提及问题。
3. 新快照增加 discussion_subjects 和 confirmation_protocol，沿用现有 SQLite payload，不做表结构迁移。旧快照仍可按原协议回答；新快照的旧 mention 键由后端映射到组并统一校验，不在前端复制答案。
4. 单组保存一份回执；兼容重复提交幂等。同实体有效回执可在同会话复用；改选撤销组及别名关联旧回执，不改变其他独立对象。操作权限继续按类型校验；公司回执不授予报价权限。
5. 不删历史重复记录，不自动创建委托、修改投资记录或发通知。若需回退代码，旧版本需重新解析新协议快照，不能把新增对象组当作旧的多个授权。

## 体验与状态

主任务是确认研究谁。复用 DSH 原生问答：明确对象一次确认，真正歧义显示候选；多对象分别确认。加载/刷新由原生 Tool 状态承担；无候选与来源失败分别反馈；跳过/自由输入不形成确认；过期、撤销、跨会话和错误版本拒绝并要求重新解析。部分回答只保存实际选中的对象。筛选无结果不适用（没有筛选器），禁用和键盘行为复用原生问答；不新增 CSS 或控件。带市场后缀的代码（如 000001.SZ）保留原文并按目录核验交易所，错误后缀不直接归并。
