# 全局提醒、稳定刷新与公开入口

状态：本地实现与受控验收完成，用户已确认交互并授权提交PR。开发基准 ac9ed0f（PR #10 最终候选，已合并）。提交前已读取最新 origin/main dc145d5；其新增行情/新闻变更与本轮无文件重叠，本轮未改写或合并主线。服务器操作需单独授权。

## 已确认体验

- 聊天页先在右下角显示提示，现有火火移动到提示框上方，敲一下后等待回应；非聊天页直接在提示框上方出现。
- 提示及火火由全局展示所有者持有，任意切页不消失、不重复敲屏；返回聊天页只有一个火火。查看或关闭后退出提醒状态，恢复聊天原有位置。
- 不抢焦点、不改输入草稿、不自动切页/滚动；浮层脱离文档流，只使用 transform/opacity 转场。减少动态效果时直接到位。
- 正式应用内提醒与明确确认后的应用内测试共用呈现组件，但标注与持久记录分开。保存、展示与已读分别表述；未知不重发。

## 实施与验证顺序

1. 补充先失败证据：公开 HTTPS 来源、旧读取隔离、提醒资格/队列/回应/历史与重复过滤。
2. 拆分首次读取、主动刷新和后台刷新；按工作状态轮询，隐藏时暂停；隔离写入和晚到读取，定位仅一次，保留草稿与布局。
3. 网页链接沿用DSH webApp可信publicUrl，内部API继续回环；完整入口缺失不猜测地址。产品站内回环链接在前端限定视图内修正到同源。
4. 复用正式/测试读取，增加全局提醒队列、持久展示游标和同源多标签协调；仅当前实际成功的 app 提醒进入主动呈现，历史初次载入不批量弹出。
5. 火火改为一个全局渲染器，聊天保留定位锚点；提示的移动/敲屏/等待不受切页影响。WebGL 失败与减少动态效果仍保留可操作提示。
6. 聚焦 Node/Python、check/build/capabilities；隔离实例浏览器验证提醒 -> 跨页 -> 聊天唯一火火 -> 回应，慢读/并发保存、草稿、滚动与布局稳定、窄屏/减少动态效果。

## 兼容与失败

不更改联系决定/正式通知准入或增加自动重试；不把客户端展示视为服务端已读。展示记录按当前浏览器/实例隔离，跨设备不承诺同步已读。页面断线保留已有提示，失败不得制造提醒。无真实模型、外部渠道或服务器测试。数据库无需迁移；回退源码/安装包即可，已存通知不删除。

## 2026-10-30 本地实现与验收

本轮已实现，结论仅适用于本地受控交互预览。新 worktree/分支为 `persistent-reminder-ui` / `codex/persistent-reminder-ui`。未提交、推送、提 PR 或更新服务器。预览使用18941/18942，验收结束后只保留API/Web，不运行worker。

实现补充：
- 共享 ReadCycle/useSnapshot 区分首次读取、手动刷新、后台读取，合并同一在途读取；取消代次使旧读取不能覆盖写入。编辑期间暂停读取，隐藏页停止轮询；委托/策略仅排队运行时快轮询，未来等待采用60秒，持仓风险15秒。
- 详情回访按目标定位一次；读取反馈预留固定行，后台进度不插入新行；新提示固定定位、模型仅用transform移动，不挤动文档流。
- 从DSH公开入口服务延迟读取publicUrl，生成宿主可点击的完整入口；缺失时明确引导顶部导航，不猜测回环地址；历史合法产品回环链接限定修正，普通本机资料/外部网页不改写。只检查新增/修改的链接节点，避免流式输出时扫描整页。
- `/notifications/in-app` 是同一通知服务的只读投影：仅本人已保存的app正式/测试消息；不调用适配器，不回收测试状态，不竞争写锁。保存不等于展示/已读。
- 展示游标及待回应ID按实例scope、本机origin保存，不保存消息正文；首次快照只建立历史基线，新ID入队，不依赖客户端时钟。Web Locks协调同源标签；旧浏览器有短租约降级，存储失效仅当前页去重，跨设备不共享。
- 同一个canvas从聊天锚点移动至提示上方，提示不会因切页自动回应；刷新恢复后不重敲。原生modal会使外部popover不可操作，因此同一展示子树临时附着当前窗口，退出时归位；关闭/稍后看仍可操作，避免导航丢草稿的详情入口明确暂缓。

### 2026-10-30 补验：连续提醒接续

用户反馈：新对话页有多条提醒时，逐条回应会重复从中间移动到角落。原因是每次队首ID变化都重置到notice，定位也跟着回到聊天锚点。

修正：以队列是否仍在呈现区分连续提醒与新一轮提醒。更换队首时首帧直接进入waiting，保留角落位置；不重新移动或敲窗。仅队列清空后释放本轮记录，保留已有450ms平滑回程。新一轮提醒仍可正常播放首次入场。
