# V1.4 旧数据导入

## 目标与来源

把用户主动选择的旧产品 JSON 数据迁入当前实例的正式领域记录。文件读取由浏览器文件选择器完成；服务与聊天不接收本地路径或任意 URL。来源基线为旧仓 `public/master` 的 `9c23b1fdb249d8192748196cb183709e8e2030f4`：

- `backend/dsh-trading-core/adapter/data_transfer.py`：trading-core schema 1–4 的分类、集合、摘要和导出函数。
- `backend/dsh-trading-core/adapter/product_package.py`：产品数据包 format 1 的范围、领域校验值和附件清单。
- `backend/dsh-trading-core/research_partner/transfer.py`：委托、修订、主体、要求、依赖和日程的导出形状。
- `adapter/schemas.py`、`adapter/manual_trades.py`：持仓、真实/模拟成交及手工成交字段语义。

这里迁移确定性业务数据，不恢复旧 Agent、模型配置或运行进程。旧实例和真实用户数据没有被读取作为测试素材。

## 用户流程与状态

设置中的“旧数据导入”提供文件选择、按类勾选、冲突规则、逐项影响预览、明确确认和持久回执。确认前可取消并重新选择分类；已提交后不会伪装成可以无损撤销，需从正式领域更正记录。

| 状态 | 页面行为 |
| --- | --- |
| 无上传 | 提供 JSON 文件选择，说明格式和大小 |
| 读取/上传 | 保留当前内容，禁用重复提交 |
| 文件无效或超限 | 显示可修正原因，不生成正式业务记录 |
| 部分分类非法 | 预览列出阻塞原因，整批禁止提交；可取消并只选择有效分类 |
| 冲突 | 默认保留当前；持仓/策略可选择使用导入值，预览展示数量与成本等前后值 |
| 过期/版本变化 | 拒绝旧预览，要求重新核对 |
| 取消 | 持久标记 cancelled，不改正式记录 |
| 连接中断/提交未知 | 禁止自动重复提交，先查同一 preview_id 的回执 |
| 成功 | 展示正式事实版本、策略/委托/档案条数和时间 |
| 无权限 | 不返回其他用户文件、预览或档案 |
| 档案为空/分页 | 说明没有旧资料；分页读取，原始记录可展开 |

复用现有 `--hh-*` 色彩、白色表面、胶囊按钮和 Form.module.css；没有引入新的主题或 UI 库。设置入口已在真实浏览器渲染；上传权限被浏览器拒绝，上传后的页面验收尚未完成，不能用组件代码或测试替代 UAT。

## 确定性映射

| 旧数据 | 新正式记录 | 不恢复的语义 |
| --- | --- | --- |
| holdings.default | investment_facts.default，正式版本和审计；明确选定冲突处理 | 不删除当前其他证券，不把未知成本补为零 |
| holdings.manual_trades、trades.entries | 支持证券的真实买卖作为历史记录，affects_holdings=false，稳定身份去重 | 不重复计算当前持仓；模拟、非买卖和零数量/价格流水仅归档 |
| 旧成交费用、时间、撤销状态 | 未提供费用为 None/fees_known=false；无时区按中国市场时间解释，保留原时间文字/精度；保留撤销状态 | 不凭空造费用、秒级精度或“有效成交”状态 |
| watchlist.default | 合并自选，使用来源或当前名称解析，无法解析明确待补 | 不擅自移出当前自选 |
| strategies | 用现有策略 definition 校验，保存 candidate，保留旧来源标识 | 不继承旧 active 状态、收益或验证通过；不能映射的规则阻塞所选分类 |
| strategy_backtests、shadows、shadow_equity、gene_archive、events_ledger、已应用演进审计 | 带来源的只读旧资料 | 不成为当前实例执行/验证证据 |
| reports、decisions、briefs、backtests、research_chat_contexts | 只读旧资料，保留结构与标题 | 不冒充 DSH 会话或新研究结果 |
| research-partner 委托及修订 | 当前 principal/instance 下的新映射 ID，暂停或保留结束；修订链/主体/待补充项保留 | 清除旧 session、triggers、联系许可；依赖 inactive，日程 disabled；每修订范围须兼容新契约，重新确认完整范围、规则、渠道后仍暂停，再明确恢复 |
| 已迁入同 ID 委托 | 保留当前正式委托，旧内容另存档 | 不覆盖当前修订或恢复旧授权 |
| 持仓原快照、修订、风险配置等剩余字段 | 原始所属集合只读归档 | 不自动重算历史净值、不重新启用旧风险监控 |
| preferences、behavior、notifications、运行任务集合 | 明确排除并给出提示 | 不迁移凭据、模型/通道配置、通知授权、队列、进程、租约 |
| 附件清单 | 记录未还原附件名称 | 不访问附件路径，不声明已恢复附件内容 |

证券范围与当前 investment/strategy 校验器一致。无法映射、超出范围、重复身份、断裂委托修订/引用会明确阻塞，不静默丢弃后声称完整迁入。档案不是完整备份恢复，用户需要保存原始导出文件。

## 持久化和失败恢复

`016_legacy_transfer.sql` 已串行注册到正式 research_partner 迁移目录。全部表与正式 investment/strategy/mandate 表复用同一 `SQLiteStore` 连接和外层事务。

- 上传最大 20 MiB，每用户最多 20 份；JSON 深度 32、总节点 100000、单文字 2 MiB。拒绝重复键、非有限数值、路径型文件名、未知格式主版本、摘要不一致。
- 上传前校验整体/领域摘要，再排除凭据字段与可识别凭据文本；只持久化脱敏候选。这里不是任意文本的完整 DLP 扫描。
- 上传按 principal 归属，可由该用户不同 DSH 会话选择；每次 prepare 绑定自己的 session/request_key。原生确认只能提交该会话的同一预览，不能跨会话复用确认。
- prepare 固化所选类别、冲突规则、逐项变化和正式状态版本摘要，有效 30 分钟。提交再次校验身份、会话、请求标识、期限和版本。
- commit 单事务写事实/版本/审计/outbox、策略、暂停委托、档案、导入审计和回执。一处失败全部回滚。新的事实 outbox 只描述本次确认导致的事实变化，不恢复旧队列。
- 未知响应先查 status；进程重启后 pending 可查，已完成返回原回执。不会自动重放业务写操作。
- archive 按 principal 过滤，身份摘要去重。移除上传只删候选并取消其 pending 预览，保留已提交记录和回执。

## 集成接口

构造 `TransferService(core_store, instance_id, clock=time.time, name_resolver=None)`；身份和 UI session 必须来自认证宿主，不接受模型提供 principal。

| 方法 | 参数 |
| --- | --- |
| uploads | `(principal)`，列出当前用户候选 |
| upload | `(principal, session, {request_key, filename, content})` |
| prepare | `(principal, session, {request_key, upload_id, selected, rules})` |
| commit | `(principal, session, {preview_id, request_key})` |
| status / cancel | `(principal, session, preview_id)` |
| preview_changes | `(principal, session, preview_id, category=None, offset=0, limit=50)` |
| remove_upload | `(principal, session, upload_id)`，只允许上传所属会话移除 |
| archive | `(principal, archive_id=None, category=None, offset=0, limit=30)` |

UI `TransferSection` 调用 `POST api/huohuo/transfer`，body 为 `{operation,...}`。桥接固定 session `ui-transfer-owner`；操作 `changes` 对应 preview_changes，其余按表同名。宿主必须有界读取 JSON（文件正文转义后会大于原文件，设置合理传输上限），认证转发给 `/transfer/{operation}`，禁止任意路由、principal/session 覆盖或地址输入。

聊天 `createTransferTools` 提供 `read_legacy_imports` 与 `import_legacy_data`，只读已上传候选/回执/档案，写操作固定 prepare → 原生用户确认 → commit。取消、自由文本、多个选项或中断不提交；提交未知返回 preview_id，请先查回执。文件上传仍从设置进入。Tool allowlist、目录、装配与 Skill 方法已同步；两项导入 Tool 已注册。

- 27 项领域聚焦用例通过：schema 1–4、产品包、所有者/会话边界、取消、过期、并发版本冲突、重复请求、回执恢复、部分非法阻断、整批失败回滚、显式重试、只读档案、费用未知与旧成交不重算。
- 使用旧基线原 `export_snapshot` 与 `build_package` 函数、合成 store 导出真实形状，再由新接口上传/预览/提交成功。这是原函数的格式互通证据，不是访问旧用户实例。
- TypeScript `tsc --noEmit` 通过；聊天程序化检查确认、自由文本拒绝、路径拒绝、会话绑定与取消通过。
- 主集成者提供的旧成交修改保护已交叉测试：默认重算拒绝；只改记录保留未知费用；明确填 0 后费用变为已知；撤销不改持仓。
- “未知当前成本在只补记录预览中不得显示为 0”已先复现再修复；保留未知成本通过。新增 5 项导入委托回归通过：不兼容范围预先阻塞、未确认禁止恢复、完整约定重新确认、新修订仍暂停且显式恢复、失败整体回滚；独立复核通过。
- 主集成真实本机 HTTP 测试覆盖上传、预览、提交、身份拒绝、事实版本、档案与回执；Node 检查原生确认、取消、伪造确认与未知结果。设置入口渲染通过，但浏览器上传权限被拒绝，因此页面上传／预览／确认／档案与刷新尚未验收，未绕过拒绝。

合成浏览器数据可从 `tests/test_transfer_fixtures.py` 的 `package(mandates=[mandate_entry()])` 生成。未写真实用户凭据、未访问用户远程服务器、未提交或推送。

DSH 0.2.1-rc.2 的缓冲路由先检查 Content-Length 并按接收字节累计限制为默认 300 MiB；产品桥读取后限制传输 JSON 42 MiB，侧车在读取前再次检查 42 MiB，原始文件上限为 20 MiB。产品桥的 42 MiB 不是浏览器请求的流式接收上限。
