## 公开资料及许可边界

固定来源为 [IDUXGRAPH / iducsite](https://villadora.github.io/iducsite/) 的五个 JSON：stats、companies、market-caps、view-data-all、network-data。2026-10-27 实查 [来源仓库](https://github.com/villadora/iducsite) 未见可确认的再分发许可；公开可访问不代表获得商业或再分发授权。状态明确返回 `license_status=not_verified`，下载预览展示来源和限制，并要求 `acknowledge_source_terms=true`。产品包不带种子或用户缓存；实际使用者须确认其用途获准，不得把确认按钮当作许可授予。

关系来自公开报告抽取与算法推断，可能遗漏或错误。`share_source=disclosed/default/inferred` 必须保留；默认展示权重不是披露比例，推断边的 share 保持 null。来源的名称、市场字段和市值也不是产品证券身份的权威主数据，不能覆盖正式实体绑定。

## 数据与失败恢复

- `root` 由当前实例显式注入，例如实例数据目录下的 `industry-chain`；禁止旧 `IC_*` 环境或旧服务地址回落。
- 种子只在确认提交时访问固定 HTTPS 来源；拒绝重定向，单文件上限 128 MiB，总上限 256 MiB。逐块计数，不信任 Content-Length；检查 JSON、最低结构和 SHA-256。
- 五文件全部通过才把 staging 改名为不可变 generation，再原子发布 CURRENT.json。查询缓存绑定用户、正式增量版本和 generation；所有可变缓存属于实例。
- 刷新失败保留旧数据。删除只删除当前实例种子，保留正式研报增量与 A 股清单。无启动下载、自动重试或自动刷新。
- 确认凭证与正式增量使用现有 Repository 的同一 SQLite，迁移为 `014_industry_chain.sql`。凭证绑定 principal、session、request_key、内容摘要、资料版本和 30 分钟有效期。
- 已提交回执可重复读取。并发提交在数据库中互斥；重复运行请求不触发第二次下载。进程启动显式调用 recovery：如果 CURRENT 已记录该操作，则恢复已发布回执；否则记 interrupted，不重放网络操作。
- 研报增量一次事务保存，非法部分导致整批拒绝。每条公司候选和推断边必须引用本用户本会话成功的 research_tool_calls；确认时重查摘要，资料变化拒绝提交。保留引用与原结果哈希，抽取结果本身不冒充经过人工核实的披露。

## 集成接口

```python
service = IndustryChainService(instance_chain_directory, execution_repository)
service.recovery()  # 只在进程启动、开始接受请求前执行
service.status(principal)
service.query(principal, path, params=None)
service.prepare(principal, session, {"request_key": "...", "action": "bootstrap", "payload": {"acknowledge_source_terms": True}})
service.commit(principal, session, {"preview_id": "ICV_...", "request_key": "..."})
```

014 SQL 已由主集成者串行注册到正式迁移目录，不在构造器中另建表。服务身份由宿主确定，不能直接相信请求 JSON 内的 principal/session。commit 只能来自既有原生确认交互，不得把模型自行产生的确认字段当用户确认。

查询白名单：

| operation | path | 参数 |
|---|---|---|
| status | /data/status | 无 |
| stats | /stats | 无 |
| companies | /companies | keyword、limit（1–100） |
| company | /companies/{code} | 无 |
| entity | /graph/entity/{key} | 无 |
| single | /graph/single/{code} | 无 |
| chain | /graph/chain/{code} | depth_up/down（0–5）、top_up/down（1–10） |
| network | /graph/network | min_degree、min_market_cap、min_share、subject_only、include_universe |

模块导出 ROUTES。桥接现有 `industry_chain_lookup` / 公司档案工具时，拦截这些路径并本地调用，不访问 loopback 旧服务。缺少种子或覆盖时抛 ToolUnavailable；缺少全 A 股清单不返回“零家公司”。查询结果带来源和资料版本。普通 network 为原种子网络；`include_universe` 的 A 股网络会叠加确认后的推断边，不能把普通 network 的原始缓存宣称为实时完整关系网络。

操作：

- bootstrap / refresh：payload 为 `{acknowledge_source_terms:true}`。
- delete / refresh_universe：payload 为 `{}`。
- clear_overlay：payload 为 `{codes:["600001"]}`，移除对应公司增量及相连推断边。
- overlay：payload 为 `{companies:[...],inferred_links:[...]}`。详见 overlay.py 的严格 schema；不能提交 shell、路径、任意 URL、模型参数或任意字典。

公司候选包括 code、source_evidence_ids、materials、products、related、metrics；材料含 name 与 suppliers，产品含 name 与 customers；每条关系包含 id/name/type/share/confidence/note。type 为 direct 或 inferred，inferred 禁止非空 share。经营指标以带明确 unit、period、note 的字符串保存，不能自行换算成正式财务事实。推断边包含 source/target/kind/item/confidence/note/source_evidence_ids。

DSH 方法顺序：先取明确对象和报告资料 → 获取已保存成功证据 ID → 抽取有依据的关系、披露期、占比或未知 → 提交结构化候选预览 → 原生用户确认 → commit → 再查询验证。没有报告证据时只解释缺口；不允许为了填满图谱编造关系。服务器注册、Skill 方法装配、设置面板及浏览器验收由主集成切片负责。
