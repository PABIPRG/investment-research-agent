# V1.4 策略后台迁移

## 范围与授权

用户已确认将旧策略保存、回测、影子验证、归因、预案与后台闭环迁入本地侧车。DSH 保留完整 Agent 责任；不恢复旧 Python Agent。计划默认关闭，用户经页面确认或原生对话确认后启用。候选建议保存、归档召回采用、演进预案应用均分别确认，不自动交易或自动应用。

本切片在独立 worktree 实施；现有 UI、持仓与外部通知不变。旧源代码基准为旧仓库缓存 `public/master` 的 `9c23b1fdb249d8192748196cb183709e8e2030f4`。运行采用当前实例的 SQLite 与当前已配置 DSH，不读取旧实例、凭据或旧用户数据。

## 能力闭环

| 旧行为 | 新的责任与实际入口 | 限制 |
|---|---|---|
| 定时影子运行 | `background.tick` 到期持久排队；复用 `workflow.execute` / `calculations.shadow_result` | 没有新交易日记录时跳过；行情不可用不补造收益 |
| 初次/周期回测巡检 | 已确认 strategy_ids；候选首测、已验证按 retest_days 重测；共用回测证据和回执 | 每项顺序执行，失败不算通过；未新增默认自动授权 |
| 事件假设生成 | 独立 events 采集任务→程序来源事件→`planner.ingest/claim`→独立 DSH→`planner.finish`→suggestions | 来源≤24小时；每事件≤3个候选；限定计划证券；模型无工具与业务写权限 |
| 归档召回 | `market.load/save` 重新读取基准→`gene_archive.revival_candidates`→待确认建议 | 不依赖此前恰好执行影子任务；缺本期市场环境时等待；确认后新建 candidate，重新回测 |
| 进化闭环 | 到期只 `evolution.evolve(apply=False)`；既有显式 apply 执行原子变更 | 自动应用被禁止；后台计划不纳入未来新策略 |
| 归因/先验/历史 | 复用既有 attribution、priors、strategy_runs、run_evidence | 旧用户数据仍需独立显式导入，不用源代码存在冒充已有数据 |
| 闭环审计 | `record_closed_loop_run` 记录本轮真实完成/部分失败 | UI 展示实际 next_at 与执行/候选研究状态 |

## 状态与存储

2026-10-28 按用户确认收敛到 V1.4 核心，详见 [统一实施与验收](V1.4-策略任务统一实施.md)。`017_unified_strategy_work.sql` 将下面三个旧计划/任务表改名为 `legacy_*` 只读归档。它们不再承担活动调度或租约。以下列出 012 的历史结构，供升级核对：

- `strategy_schedules`：principal 唯一计划、revision、明确范围/时间/操作、下一次执行时间。每次改约或停用增加 revision。
- `strategy_background_jobs`：principal/revision/day/strategy/action 唯一键。并发 tick 只认领一项；复用 `strategy_runs` 回执、交易日行情与证据。
- `strategy_events`：来源事件 id 与内容指纹不可变。
- `strategy_planner_jobs`：来源事件与计划版本唯一，30 秒租约、120 秒总时限；worker token 之外还验证 attempt token。
- `strategy_suggestions`：事件/归档建议，pending→accepted；正式策略只在确认事务中新增。

当前正式计划由 `mandates / mandate_revisions / mandate_schedules / mandate_generation` 保存，类型为 `strategy_validation`。到期和来源事件进入核心 `research_jobs → execution_jobs → executions → attempts`，候选与计算共享租约、fence、取消和恢复。`strategy_events / strategy_suggestions / strategy_runs` 继续保存领域资料和结果。旧终态只导入已消费业务槽与历史，不伪造成功 attempt；旧在途工作明确中断，无法证明授权的旧计划保持暂停。

页面/聊天通过既有 `prepare → 用户确认 → commit` 增加 `schedule`、`accept_suggestion` 两种动作。停止/改约在同一事务取消旧排队和在途任务；计算完成写入前再校验运行状态、计划版本和策略领域版本。取消后的迟到结果不会覆盖状态或写入策略。

进程启动先调用统一 `Repository.recover(abandoned=True)`，再同步策略投影：未开始任务保留，已运行任务标记 interrupted，不重放未知计算。DSH 已发送后中断或提交回执未知时保留租约到期状态，不重新发模型请求。重复 finish 只读原回执。重启停机多日仅处理当前已完成日线，不能声称停机期间一直运行。

工作日只是调度节奏，不被当作交易日判断。影子记录以行情实际日期为准，同交易日去重；归档召回要求当前截止日有效基准，无数据或休市不生成召回。

## 侧车与发行装配契约

`sidecar/huohuo/strategies/worker_http.py` 只供主 server 验证 worker token 后调用，传入去掉 `/worker/` 的路径段。不得路由给 user token。

当前 worker 使用统一接口：

| POST 路径 | 请求 | 返回 |
|---|---|---|
| `/worker/claim` | `{worker_id,lane:"strategy"}` | null 或含 execution_id / attempt_id / job_id 的绑定任务 |
| `/worker/attempts/:id/heartbeat` | `{}` + X-Attempt-Token | 统一租约；计划暂停、改约、fence 或超时即拒绝 |
| `/worker/attempts/:id/runtime` | session_id / message_id | DSH 会话回执，计算任务不伪造模型收据 |
| `/worker/attempts/:id/strategy-run` | `{}` + X-Attempt-Token | 计算并原子保存业务结果、证据和执行回执 |
| `/worker/attempts/:id/strategy-result` | 候选或失败 JSON + X-Attempt-Token | 校验后保存建议与核心结果；重复相同提交返回原回执 |
| `/worker/recover` | `{}` | 核心租约恢复，不重放未知执行 |

以下旧路径作为内部兼容适配器保留，全部委派到上述核心，不持有第二套租约：

| POST 路径 | 请求 | 返回 |
|---|---|---|
| `/worker/strategies/tick` | `{}` | 单项结果或 idle/busy；请求超时须覆盖有界行情计算 |
| `/worker/strategies/events` | `{events:[...]}` | `{queued:[job_id]}` |
| `/worker/strategies/planner/claim` | `{worker_id}` | null 或 job/lease/event/priors/规则契约 |
| `/worker/strategies/planner/:id/heartbeat` | `{}` + X-Attempt-Token | lease_until |
| `/worker/strategies/planner/:id/finish` | 完成或失败 JSON + X-Attempt-Token | 持久回执与待确认 suggestion ids |

事件必须由可信程序来源构造，形状为 `{id,source,observed_at,title,summary,securities:[{code,name}],evidence_ref}`；时间是 Unix 秒，单次≤100条、证券1–3个。id≤200、source≤200、title≤300、summary≤4000、evidence_ref≤300。证券必须是已确认策略范围的子集。freshness 合格才交给 ingest；错误来源不可假设成空事件。

模型只返回 `{status:'completed',candidates:[{name,kind,params,securities,rationale,direction}]}`，最多3项，或 `{status:'failed',error}`。不能提供来源 id、正式状态、收益和确认信息；程序重绑证券名称与证据。

发行集成由主代理串行完成：

1. `package.json` 增加 `./strategy-worker` 导出至 `lib/product/strategy-worker.js`，打包 `product/profile`。
2. 安装 `huohuo-strategy-worker` 独立 DSH profile；使用基础 SDK bundles 和 `product/profile/huohuo-strategy-worker.yml`。该 patch 替换研究工具插件，禁用全部内建工具；不得同时装配普通聊天或 bounded-quote 写入插件。
3. `distribution/strategy-worker.ts` 导出 `runStrategyPlanner`。使用实例配置 provider/model，120秒截止、5秒心跳、AbortSignal 关闭客户端。初始化后校验 job-bound ACK、profile 名称和空 tools。
4. 初始化 `Strategies(...,event_source=callable)`，callable 接收去重的已授权证券列表（最多20只），使用现有新闻来源返回事件列表；来源失败应抛异常，不能返回空成功。events 作为类型化策略委托的核心任务，按已确认 daily_time 采集。worker 的策略资源消费者调用统一 claim，依据任务类型分派；将接纳的新来源事件送入 ingest。不要并发创建另一套 Python 调度器，也不要用旧通知模块发送消息。
5. 主服务启动恢复与 worker-only 路由接线；更新能力目录/注册文档，UI bridge 已复用原策略确认路径。

## 用户入口

- 验证与演进：后台验证摘要、设置/调整/停止计划，明确策略选择、动作、北京时间、回测间隔与样本；预览后确认。
- 同页待确认候选：名称、证券、规则、研究理由和来源；查看并确认保存。归档召回显式标记，保存后仍待回测，不混入现有收益。
- 同页执行记录：实际排队/运行/跳过/失败/中断/停止。运行详情沿用已有回执与证据。
- 对话 `read_strategy_records` / `manage_strategy`：查询同一计划和建议，`schedule` / `accept_suggestion` 同样强制原生确认。

## 验证与尚待集成验证

本切片的受控测试采用临时 SQLite 和合成 OHLCV，不访问真实行情或真实模型。覆盖默认关闭、日程去重、计划改约、取消拒绝迟到结果、重启恢复、来源时间/证券隔离、租约过期、候选确认持久化、真实基准读取后的归档召回、既有保存/回测/影子/预案链路。

## 调度顺序修正

同日按新闻采集→回测→影子验证→归档召回→演进预案执行，先更新基准再生成预案，避免预案在生成后立即被同批基准变更失效。跨日恢复先把旧日未开始任务明确取消并注明合并到最新日程，再按约定生成当前截止日任务；在途未知任务保持 interrupted，不重放。
