# 安装、启动与恢复

## 环境与边界

要求 Node.js ≥24.8.0、npm（已验证 11.x）、Python ≥3.11；DSH 固定为 0.2.1-rc.2。当前本地证据仅覆盖 macOS arm64、Python 3.14.4，不能据最低版本声明推断其他平台通过。依赖锁通过 npm/PyPI 下载，tgz 不含全部依赖，因此不是离线安装包。

所有命令在产品源码根执行。以下目录与端口是示例；每位开发者选择自己的空闲端口及实例目录，端口占用时换端口，不停止别人的服务。启动默认只监听 127.0.0.1。服务器部署、端口公开和系统自启动不在本候选验证范围。

## 准备源码与构建

```sh
node --version
npm --version
python3 --version
npm ci --ignore-scripts
npm run check
npm run build
node scripts/package-release.mjs
```

macOS/Linux 示例；Windows 虚拟环境、路径和进程行为尚未验收。运行产品不要求开发依赖，但从源码构建需要上述 npm 安装。

## 首次安装到持久实例

```sh
export HUOHUO_INSTANCE_DIR="$HOME/huohuo-data/main"
export HUOHUO_API_PORT=18810
export HUOHUO_WEB_PORT=18811
export HUOHUO_TGZ="$PWD/artifacts/release/huohuo-research-agent-1.0.0.tgz"
node lib/distribution/cli.js init "$HUOHUO_INSTANCE_DIR" "$HUOHUO_TGZ" "$HUOHUO_API_PORT"
```

实例目录必须不存在。CLI 创建独立 Python 环境并安装锁定依赖，再安装 worker Profile。较慢网络首次安装需要数分钟。`HUOHUO_PYTHON` 可指定用来创建环境的解释器，不会把旧虚拟环境复制到实例。

## 正常启动与模型配置

```sh
node lib/distribution/cli.js start "$HUOHUO_INSTANCE_DIR" "$HUOHUO_WEB_PORT" --no-open
```

终端显示本机带访问能力的入口 URL；只在自己的浏览器打开，不把 URL 发到群聊。通过顶部账号菜单中的「设置 → 模型」在本机配置所需模型凭据；首次缺少凭据时直接显示 API Key 配置引导。本产品不装配 DeepSeek 平台账号登录、余额或充值入口。配置其它提供商后，在聊天输入区选择对应模型。聊天模型与实例后台研究模型分别核对，界面能聊天不证明 worker 的模型已可用。当前默认后台为 `deepseek-official / deepseek-flash`；其他后台模型的配置与兼容性需要单独验证，勿只改聊天选择就宣称全链路切换成功。

数据位置：实例根 `instance.json` 保存身份及能力凭据；`business.sqlite3` 保存业务；`dsh/` 保存两个 Profile、会话与本机模型配置；`workspace/` 为隔离工作目录；`runs/` 保存执行尝试；`cache/` 为依赖缓存。实例是私有数据，不能提交 Git 或作为交付附件。

聊天浏览器关闭不停止终端中的后台。Ctrl+C 停止本次产品服务及子进程；重开同一实例可查询旧任务。不承诺关机、休眠或退出终端后仍持续运行，也没有系统开机自启。

## 安装中断与更新

```sh
node lib/distribution/cli.js repair-install "$HUOHUO_INSTANCE_DIR"
```

只修复明确指定实例的依赖与中断阶段，保留身份、数据库和用户 patch。不要删除实例重新 init 来“解决”下载失败。包 SHA 不一致、用户修改过受管 patch、外部 Python 依赖不完整等情况会明确拒绝，先核对原因。

更新前停止自己的实例并备份完整私有实例（备份也不进入源码）。同事在新源码根执行：

```sh
HUOHUO_INSTANCE_DIR="$HUOHUO_INSTANCE_DIR" HUOHUO_WEB_PORT="$HUOHUO_WEB_PORT" npm run update:instance
```

该入口会构建、打包并预检受管聊天配置，再刷新两个 Profile。当前支持本轮以前的已知受管 patch；未知修改不覆盖。保留程序包不能保证新数据库可被旧程序读取；涉及 schema 变更必须另做迁移、备份及恢复验收。完整产物级升级/回滚矩阵仍未通过。

## 常见问题

- `端口已占用`：选择自己的空闲端口；不要杀死未知进程。
- npm/PyPI 下载或 DNS 失败：核对本机网络和批准的包源，再恢复安装；不能据沙箱限制认定上游服务故障。
- 模型未配置：在本机设置填写；不要把密钥贴进聊天、截图或日志。
- 任务 queued/running：表示接受/执行，使用界面回查，不能重复提交以“加速”。
- 资料失败或单位/口径未知：保留失败/unknown，不能补数或当作条件不成立。
- 源码冒烟首次下载较慢：`HUOHUO_SMOKE_INSTALL_TIMEOUT_MS` 默认 900000，范围 1000–3600000；可用 `HUOHUO_SMOKE_RESUME` 指向启动器自己的测试根恢复中断安装。恢复必须匹配运行源码指纹和原 tgz 完整性；运行代码改变或旧报告缺少指纹时明确拒绝，避免新测试搭配旧 Profile。文档修改不影响该运行指纹。

## 人工冒烟与内部回放不可混用

人工验证“帮我记录恒科 ETF 持仓”等自然语言，请使用上面的 `huohuo start` 持久实例入口，并先在页面配置真实模型。`smoke:skills -- --serve --business` 仅用于开发者的固定场景回放：模型适配器被测试 fixture 替代，只接受 `回放 B01` 等编号，没有真实 API Key 配置能力，不能交给用户当正常产品入口。
