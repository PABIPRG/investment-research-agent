# 本机使用流程与交付工作

整理日期：2026-10-30。实现核查基准：`af05703148b91e068b8456c8163088cba38c0621`。本文按“用户操作步骤 → 我们的工作”组织本地试用发行的收尾范围；目标体验、现有代码和待验收项分别标记，不把计划写成已完成。

## 1. 用户最终拿到什么

交付目标是一个火火 npm 主产品包及同版 `.tgz`。用户安装产品、准备本地实例、启动浏览器并配置模型，不需要克隆源码、运行 build 或自行装配 DSH。

火火安装层准备固定版本 DSH、产品插件和 Python 业务环境；DSH 运行完整 Agent，火火业务程序持有委托、投资事实、证据和通知的正式状态。代码归属与调用关系见[架构图第 3 节](当前架构与装配.md)。

当前仍为候选：`package.json` 保留 `private:true`，打包脚本也仅生成验证产物，尚无公开 npm 安装入口。初始化仍要求现有 `.tgz` 路径。以下是要交付的用户流程，不能将其当作已发布产品的安装命令；当前可执行的开发者/候选包操作见[启动指引](启动指引.md)。

## 2. 操作步骤 → 我们的工作

下表“我们的工作”由开发与验收人员承接；用户只在列明的产品选择、凭据配置和实际使用环节操作。完成文档或 PR 不会自动完成这些工作。

| 步骤 | 用户的操作 | → 我们要完成的工作 | 当前基础与差距 | 该步骤的验收结果 |
|---|---|---|---|---|
| U01 获取说明 | 查看版本、支持环境和安装方法 | 明确首批 OS/CPU、Node/Python 要求、分发渠道和许可；整理面向使用者的简短说明 | 已有开发指引；历史运行证据主要覆盖 macOS arm64，首批正式支持范围仍待确认 | 用户能判断自己的电脑是否支持，知道安装来源和必要前提；不把最低版本声明当成平台已验收 |
| U02 安装火火 | 安装一个火火产品包 | 生成包含运行代码、UI、Skill、Python 业务源码和锁文件的同版包；提供稳定 CLI；安装匹配的 DSH 依赖 | 已有 `huohuo` bin 和打包检查；尚为 private 验证产物 | 仓外只拿到候选包即可安装，不依赖开发仓、源码 build 或预装全局 DSH |
| U03 准备环境 | 按提示补齐本机运行环境 | 提前检测 Node/npm/Python，明确缺失或低版本的修复方法；校验实际锁定依赖是否支持该平台 | 声明 Node ≥24.8.0、探测 Python ≥3.11；创建 venv，不自动安装 Python 解释器；完整依赖仍需联网下载 | 支持组合可安装；不支持组合准确停止并给出修复步骤；不静默更改系统环境 |
| U04 初始化 | 确认实例数据目录，开始首次准备 | 收口无需手动找 `.tgz` 的正式入口；准备实例身份、业务库、Python 环境和 DSH Profiles；展示阶段与恢复办法 | `init`、`repair-install` 已有；`init` 当前仍读用户传入的 `.tgz`。默认目录及普通用户交互待收口 | 首次成功、重复执行不覆盖已有身份；中断后恢复同一实例；数据独立于 npm/npx 缓存 |
| U05 启动 | 启动火火并打开本地页面 | 一个入口管理侧车、worker 和 DSH Web；打开本次进程的认证入口；处理端口冲突、启动失败及本次子进程清理 | `start` 已装配；当前默认监听 127.0.0.1，需验证固定最终包的真实首次进入 | 用户实际浏览器加载首页、认证后刷新可用；不复用旧 token，不停止未知占用进程 |
| U06 配置模型 | 在设置中填写凭据，选择所用模型 | 安全保存凭据；清楚区分前台聊天和后台研究模型；收口配置检查和错误提示 | 模型设置入口已有；前台选择不自动代表后台切换成功；缺少配置时不能承诺后台可用 | 凭据不进入聊天或日志；所选前台和后台配置可核对；涉及真实调用的测试经明确触发并说明费用影响 |
| U07 第一次研究 | 提出研究问题，查看进度与结果 | 从正常产品入口验证真实模型、资料与证据链；明确成功、来源失败、缺资料和 unknown；提供可回查结果 | 已有工具与执行链，受控回放不能证明真实研究质量 | 固定候选包完成代表性真实问题；结果可追溯来源，缺数据不补造，失败不冒充成功 |
| U08 维护投资事实 | 按需录入或修订持仓、自选 | 页面和聊天共用领域服务；写入前确认；保护事实版本、重复请求和持久性 | 已有双入口及权威存储基础；仍需候选包代表路径验收 | 保存、刷新、重启后数据一致；空集合与报价缺失分别呈现；修订可回查 |
| U09 持续跟进 | 明确交代对象、条件、时间和联系约定 | 展示并确认可执行规则，建立正式委托；提供查询、修改、暂停、恢复和结束；未支持的约定明确澄清 | 已有委托核心、Hook、执行门禁及程序条件；任意自然语言不自动成为可执行规则 | 用户能核对实际保存的约定；普通讨论不变成持续授权；暂停或旧代次阻止新的副作用 |
| U10 联系与通知 | 按需开启提醒、配置渠道和委托联系范围；明确需要时发送一条测试 | 保留全局开关与每项委托渠道授权；安全表单保存凭据；测试先准备、再核对目标并确认；正式通知保留最终许可和回执 | 已有应用内、企业微信、Server 酱、SMTP、确认式测试和网页提醒投影；外部真实送达仍需当次授权与验收；unknown 对账入口未完整闭合 | 配置保存不自动外发；测试与正式委托分开；受理/送达/已读分别解释；unknown 不盲重发；测试忽略静默须明确告知 |
| U11 退出与重开 | 关闭网页或停止程序，之后再次启动 | 稳定复用原实例、会话、配置与业务状态；明确浏览器关闭、终端退出和休眠对后台的不同影响 | 持久实例已有；当前没有系统自启；运行中途恢复与积压仍须按任务契约验收 | 重启后数据可查；不复活旧租约或重发未知通知；用户知道退出终端/休眠后不能承诺持续跟进 |
| U12 更新版本 | 安装新版，继续使用原数据 | 面向已安装用户提供升级入口；预检兼容性、备份与必要迁移；处理用户配置、升级失败和恢复 | 有开发者更新脚本与配置保护；普通用户升级入口、完整升级/回退矩阵仍待收口 | 从明确旧版升到候选版保留数据和配置；失败可诊断；数据库回退有证据，不能只换旧程序包 |
| U13 卸载与数据 | 卸载程序，决定保留、备份或删除个人数据 | 区分包文件与私有实例；说明数据位置；删除须由用户明确选择；提供可理解的保留/恢复方式 | 程序和实例已分离；使用者卸载及数据管理说明待补 | 卸载程序不静默删除实例；用户能找到保留数据；敏感备份不混入产品分发 |

## 3. 按用户路径组织交付批次

| 批次 | 对应步骤 | 研发与验收工作 | 进入下一阶段的条件 |
|---|---|---|---|
| A 安装与启动收尾 | U01–U06 | 支持范围、包入口、环境预检、免手动 tgz 初始化、持久实例、认证进入、模型配置核对 | 在独立验证目录从固定包完成首次安装和启动；不读取开发者或旧用户实例 |
| B 固定候选包试用 | U07–U11 | 一次真实研究、代表性事实读写、正式委托、开放渠道范围、退出重开与故障解释 | 用户拿到的包与被验收的包 SHA 一致；真实与受控证据分开，未开放能力明确列出 |
| C 分发与版本延续 | U02/U12/U13 | 发行渠道与许可、版本/校验信息、安装说明、升级/恢复、卸载与数据保留说明 | 分发授权独立取得；后续版本发布前完成相应升级证据，不把 PR 或包版本号当作发布完成 |

首轮本机试用的最小闭环是 **U01–U07 加 U11**：没有开发仓库的环境中取得候选包 → 安装 → 初始化 → 启动 → 配置模型 → 完成一次真实研究 → 退出重开并回查数据。U08–U10 按本轮实际开放范围验收；未验收的能力不能被默认宣传为已完成。

公开 npm 发布、系统自启、跨平台矩阵和真实通知不是本次文档 PR 的执行范围。`.tgz` 小范围试用与 npm registry 分发共用主产品包，但入口与渠道验收分别记录；通过 tarball 启动不证明持久 npx 或公开 registry 路径已通过。
