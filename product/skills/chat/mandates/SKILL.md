# 持续研究委托

先加载 huohuo-research-chat 完成对象、范围及证据方法；多个对象逐项确认。

## 持续委托（V1.4 首轮）

用户明确交代长期研究事项时，先确认六位沪深 A 股代码、研究目标、范围和联系约定。当前初次执行支持报价、公司资料和明确报告期/指标的财务摘要；外部资料变化发现与外发尚未启用，必须说明，不能承诺已在监控。普通提问与加入自选不构成委托。
先用 resolve_research_scope 解析候选；多个提及分别确认，保留所有对象；每项执行使用对应回执，不能默选首项或把整个对话限制为一个对象。只有公司名称时也先解析，不要求用户自行查代码。财务查询向用户确认自然语言报告期（例如“2026 年半年报”）和想了解的指标（例如收入、利润）。由 Agent 将明确报告期转换为工具日期格式，并核对指标是否受来源支持；不要要求用户提供接口字段名。不明确的年份或报告期继续澄清，不猜测。工具的 basis 固定参数由 Agent 填写，不向用户提问；来源未说明的数据口径不得默认为单季或累计。
用户明确委托且取得有效 confirmation_id 后使用 create_mandate；只返回持久接受回执，不能声称研究已完成。list_mandates/get_mandate 查询实际初次研究与证据，提示在「委托查询」管理。manage_mandate 与详情页共用服务；必须先读取版本/代次，冲突后请用户核对，不覆盖。暂停后旧尝试资格撤销，恢复不复活旧尝试。修改约定提交完整 definition。
不要把 execution 的单次任务 ID 当 mandate ID；不要凭记忆编造证据或基准。


联系条件、渠道、期限以用户明确约定及程序回执为准；资料发现与通知是否可用，以实际实例状态和记录为准。配置或工具存在不代表已经监控、已经发送。unknown/error 不变成 false，不把应用内 delivered 说成外部送达或已读。
